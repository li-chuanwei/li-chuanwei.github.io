## Context

参见 `proposal.md` 的 Why。当前首页使用 React 组件管理主题按钮和导航内容，视觉样式集中在全局 CSS 中；顶部导航原有吸顶定位，主题偏好存储在浏览器本地存储中。变更需要保持零新增依赖，并兼容现有响应式断点与减少动态效果规则。

## Goals / Non-Goals

**Goals:**

- 用单一滚动状态驱动导航栏边框、玻璃背景和宽度变化。
- 让首次绘制与 React 状态使用一致的默认深色主题，避免首屏闪白。
- 让上下导航栏在桌面端和移动端具有同一尺寸基准。

**Non-Goals:**

- 不建立全局主题 Context 或引入状态管理库。
- 不复制参考站点的品牌样式、导航内容或完整动画系统。
- 不调整主页其他区块的布局和数据。

## Decisions

### 使用布尔滚动状态和被动监听器

顶部导航以约 80px 为阈值切换 `is-scrolled` 状态，滚动监听器使用被动模式。相比逐帧计算宽度，此方案只表达两个稳定状态，逻辑简单且不会阻塞滚动线程。

### 使用 CSS 宽度过渡完成内收

导航栏保留固定边框尺寸，通过 CSS 同步过渡宽度、边框、背景、阴影和模糊效果。桌面端从现有容器宽度收至 1040px，移动端按视口留白计算。相比缩放整个元素，宽度过渡不会压缩文字和图标。

### 使用布局前同步主题

HTML 根节点声明深色首屏，React 在布局阶段同步已保存偏好和浏览器主题色。相比普通副作用，这能降低主题切换前的可见闪烁；相比新增主题框架，它保持当前应用规模所需的最小实现。

### 复用响应式与减少动态效果规则

桌面端上下导航统一为 50px 高，移动端统一为 48px 高；既有 `prefers-reduced-motion` 规则继续将过渡时间压缩到近乎即时，无需新增脚本分支。

## Risks / Trade-offs

- [频繁触发滚动事件] → 状态值只在跨越阈值时发生实际变化，并使用被动监听器。
- [宽度过渡产生重排] → 只动画单个吸顶导航容器，且不改变周围文档流占位。
- [本地存储不可用] → 当前实现沿用项目既有存储方式；若未来需要受限环境支持，再引入安全读写封装。
- [小屏内容空间减少] → 移动端采用较小的左右内收量，并隐藏中间说明文字。
